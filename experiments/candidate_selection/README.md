# Candidate selection experiments

This experiment compares reranking depths equal to the requested result limit,
50 and 100; zero-score BM25 exclusion on/off; and dependency boosting before
reranking on/off. Models, reranker input and final score weights stay fixed.

The [12-query pilot](results/2026-11-02/report.md) contains 288 measured searches.
It does not establish a winning configuration. Increasing depth admits more
labeled targets but loses one from the final output. Default serving behavior
is unchanged.

## Contents

- `runner.py`: the exact runner used for the pilot.
- `patches/lean-explore.patch`: opt-in candidate controls and in-memory traces.
- `tests/`: synthetic regression tests for selection, tracing and evaluation.
- `results/2026-11-02/`: public query subset, measured records and provenance.

The engine patch is against the public commit recorded in
[patches/bases.json](patches/bases.json). It does not change serving defaults.

## Prepare the engine

Use a separate checkout. The preparation command refuses a different base or
a dirty working tree.

```sh
git clone https://github.com/lean-explore/lean-explore.git /path/to/lean-explore
git -C /path/to/lean-explore checkout 17b9d6c87a2bf0dc4ea27de05da8a1c9965391b7
python experiments/candidate_selection/prepare_engine.py --checkout /path/to/lean-explore
python -m pip install -e "/path/to/lean-explore[local]" pytest pytest-asyncio
```

The helper copies `runner.py` to the engine's `scripts/candidate_selection.py`.
That location preserves the runner's source-fingerprint paths. The engine
patch alone contains no dataset or model weights.

Run the synthetic tests from this directory:

```sh
python -m pytest -q
```

The fixtures use real SQLite, BM25 and FAISS data with fake model scores.
They require the patched engine and its local dependencies, but never download
models or call a model API.

## Reproduce the pilot

Run `prepare_pilot.py --out /path/outside/repository/pilot` to download the
recorded public assets and pinned models, verify the corpus checksums, and
copy the public queries. The corpus is about 3.9 GB; the two models add about
2.4 GB. Large assets and generated reports stay outside the checkout.

The source dataset and license are linked in
[pilot-provenance.json](results/2026-11-02/pilot-provenance.json).
The helper prints a command for each output limit. Execute them from the
prepared engine checkout. They use the same corpus, models, queries and seed
as the pilot. GPU and library versions affect latency and may affect ties;
the result files record the original package versions.

The runner warms the engine, shuffles query and variant order, and evaluates
all 12 variants for every query. Errors stop the run. Existing output files
are not overwritten. A relevant target absent from the corpus or excluded by
a package filter fails validation before measurement.

## What the traces measure

`SearchTrace` records ranked declaration IDs at raw/filtered BM25 retrieval,
semantic retrieval, fusion, selection, package filtering, reranker input,
combined reranking and final output. Times are cumulative milliseconds.

The report stores target ranks and candidate counts at each stage, final
result IDs, hit rate, recall, reciprocal rank, binary nDCG and latency.
These metrics use only the supplied labels. Unjudged declarations may be
relevant. Trace collection adds overhead; these timings are not load tests.

Controls held fixed include the top-500 fusion cut, package filtering after
that cut, autogenerated-name filtering after reranking, the existing fusion
formula and final score weights. Disabling the selection boost preserves
the dependency term in the final score. Increasing the pool also changes
pool-normalized final score components.

Use private query files only in a private environment. A report omitting raw
query text can still reveal information through identifiers and results.
Only the explicitly reviewed public pilot is tracked here.

## HTTP integration

The matching `lean-explore-app` change, an optional
`LEAN_EXPLORE_SEARCH_RERANK_DEPTH` that separates reranking depth from the
HTTP result limit, is in that private repository
(lean-explore/lean-explore-app#66) rather than here. It is not needed to run
the benchmark. Hosted MCP already supports a separate depth.
