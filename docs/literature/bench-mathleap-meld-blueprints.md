# MathLeap evaluation sets: MELD and the Blueprints retrieval set

- **Kind:** benchmark / dataset (plus fine-tuned embedding models)
- **Links:**
  - Paper: https://arxiv.org/abs/2606.23959, "Does My Embedding Reflect That A=B? Evaluating Mathematical Equivalence in Embedding Models"
  - Code: https://github.com/uw-math-ai/math2vec
  - Data: https://huggingface.co/datasets/uw-math-ai/MELD-dataset and https://huggingface.co/datasets/uw-math-ai/Math2Vec-embedding-dataset
  - Models: https://huggingface.co/uw-math-ai/MathLeap-Qwen-8B and https://huggingface.co/uw-math-ai/MathLeap-Octen-8B
- **Authors / org, date:** Jiaying Ye, Samarth Rao, Leo Carlin, et al. (University of Washington, uw-math-ai). arXiv June 2026 (v2 dated 26 Jun 2026).
- **Status:**
  - MELD is on Hugging Face under Apache-2.0.
  - The models are Apache-2.0 (per Legendre's leaderboard).
  - The math2vec repo has no license according to the GitHub API.
  - Whether the Blueprints evaluation set is published as a standalone dataset is unverified; I did not find it among the uw-math-ai Hugging Face datasets.

## What it is

1. **MELD (Mathematically Equivalent, Lexically Different pairs).** 270 pairs of statements, in natural language and LaTeX, that are mathematically equivalent but phrased in different fields' vocabulary, for example vector spaces vs. module theory. The pairs cover 9 pairs of subfields and were generated by Claude Opus 4.7, 30 pairs per subfield pair. The task: given one statement, retrieve its partner among all 540.
2. **Blueprints.** 3,729 pairs of a Lean statement and its natural-language description, drawn from 68 Lean blueprint dependency graphs. The task is informal description → Lean statement.
3. **Held-out FrenzyMath split (Appendix A).** Six directed retrieval tasks between informal descriptions, Lean types and Lean signatures, built from `mathlib_informal_v4.16.0`, reported with R@1/5/10 and MRR.

## How it works

- Exact nearest-neighbour search over L2-normalized embeddings.
- Instructions applied on the query side only.
- Metrics: Recall@k, MRR, and mean rank of the equivalent pair.
- Also reports MIRB nDCG@10 on 3 tasks: MO duplicates, mathlib retrieval, and Lean premise retrieval.

## Evaluation

- **MELD:** the best off-the-shelf model, Octen-Embedding-8B, reaches R@1 of only 25.0. Fine-tuning Qwen3-Embedding-8B lifts R@1 from 17.0 to 27.2, R@5 from 47.8 to 63.1, and mean pair rank from 16.1 to 9.7.
- **Blueprints (Table 3):**

| Model | R@1 | R@5 | R@10 |
|---|---|---|---|
| Qwen3-Embedding-8B | 59.52 | 90.13 | 94.11 |
| Octen-Embedding-8B | 64.32 | 92.60 | 96.37 |
| MathLeap-Qwen-8B | 64.73 | 93.10 | 96.44 |
| MathLeap-Octen-8B | 64.69 | 92.80 | 96.92 |

- **MIRB, mathlib retrieval nDCG@10 (Table 4):**
  - Qwen3-Embedding-8B: 0.559
  - Octen-Embedding-8B: 0.653
  - MathLeap-Octen-8B: 0.667
  - Lean premise retrieval dropped after fine-tuning (0.103 vs. 0.136 for Qwen3-Embedding-8B).
- **Legendre, MathlibQR:** MathLeap-Qwen-8B scores nDCG@10 0.572 and R@10 72.8%. Legendre labels the model "in-domain" because it was trained on the same informalization family that Legendre's corpus renders.

## Relevance to lean-explore-bench

- **MELD** probes one failure mode directly: the same mathematics in different vocabulary, e.g. "basis" vs. "linear iso with a free module". This is the axis on which MathlibQR's special-case and slogan styles are weakest. It is a cheap diagnostic, but it is informal ↔ informal and does not query Mathlib itself.
- **Blueprints** is a realistic source of informal → formal pairs: human-written blueprint text matched to Lean declarations from real projects, not only Mathlib. That makes it a candidate way to get non-synthetic queries at scale. A caveat is that many blueprint declarations live outside Mathlib, so engines that index only Mathlib cannot find them.
- **Warning:** training on `mathlib_informal_*` makes results on any benchmark whose corpus uses the same informalizations in-domain. A benchmark needs a train/test contamination policy for fine-tuned models.
